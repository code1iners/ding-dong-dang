# 제보는 앱이 아니라 개인 호스팅 n8n의 폼이 받는다

딩동댕의 "의견 보내기"는 앱 안에 폼을 두지 않고, 개인 호스팅 n8n의 Form Trigger 페이지를 기본 브라우저로 연다. 같은 경로를 meka-base-jeju 등 다른 개인 제품도 쓰게 하려는 것이 목적이다. 제품마다 플랫폼(Electron, 웹, React Native)이 달라 화면을 각자 만들면 관리할 곳이 제품 수만큼 늘어나지만, n8n 폼이면 앱 쪽 개발은 주소를 여는 단추 하나로 끝난다.

제품마다 Form Trigger를 하나씩 두고(`/form/<저장소 이름>`, 딩동댕은 `/form/ding-dong-dang`), 모두 같은 처리 흐름으로 이어진다. 제출된 제보는 n8n Data Table에 쌓고 Gmail(SMTP)로 알린다. 제품은 어느 폼으로 들어왔는지로 정한다. 앱 버전과 OS는 각 앱이 폼 주소의 쿼리(`version`, `os`)로 채우고, 폼은 이를 숨김 필드로 받는다. 경로와 쿼리 이름 규칙의 원본은 n8n 워크플로의 설명과 스티키 노트이고, 이 저장소는 자기 경로만 따른다.

## Considered Options

- **앱 안 폼 → n8n 웹후크로 POST**: 브라우저로 넘어가지 않고 실패 처리도 앱이 할 수 있지만, 제품과 플랫폼마다 폼 화면을 만들고 항목을 바꿀 때마다 앱을 배포해야 한다.
- **Discord로만 받기**: 알림은 되지만 나중에 LLM이 "아직 분석하지 않은 제보"를 꺼내 갈 상태 있는 저장소가 없다.
- **GitHub Issues로 받기**: 익명 사용자의 글이 저장소 이슈로 바로 올라가고, 이 저장소의 `.scratch/` 로컬 이슈 규칙과도 맞지 않는다.
- **열기 전에 서버 상태 확인**: 실패 시 줄을 숨기면 기능이 이유 없이 사라지고, 확인 요청이 설정을 열 때마다 개인 서버로 간다. 누를 때 확인하는 안도 검토했으나 지금은 확인하지 않기로 했다.

## Consequences

- 배포된 앱마다 폼 주소가 들어가므로 n8n 호스트와 경로는 바꾸지 않는다. 바꾸면 업데이트하지 않은 PC의 "의견 보내기"가 끊긴다.
- n8n 서버나 워크플로가 꺼져 있으면 제보를 받지 못하고, 사용자는 브라우저의 연결 오류를 본다. 앱은 이를 알지 못한다.
- `version`과 `os`는 주소를 고치면 바뀔 수 있는 참고 값이다. 값을 채우는 책임은 각 제품이 진다.
- 딩동댕이 GitHub 말고 다른 서버로 데이터를 보내는 첫 경로라서, README에 무엇이 어디로 가는지 적는다.

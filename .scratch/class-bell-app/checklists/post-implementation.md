# 구현 뒤 수동 통합 테스트에서 확인할 것

지도의 티켓에서 사람이 해야만 하는 확인을 모은 목록이다. 티켓의 검증은 에이전트가 하는 것만 두고, 여기 있는 것은 모든 구현이 끝난 뒤 실제 앱을 써 보면서 확인한다. 스펙을 쓸 때 이 목록을 수동 통합 테스트 항목으로 옮긴다.

## 학원 PC 환경 ([학원 PC의 Smart App Control 상태 확인](../issues/13-academy-pc-sac-check.md)에서 넘어옴)

- Windows 보안 > 앱 및 브라우저 컨트롤 > 스마트 앱 컨트롤 설정의 상태(켬, 평가, 끔).
- Windows 버전(설정 > 시스템 > 정보)과 PC 대수.
- 설치된 타사 백신이 있는지.
- 노트북인지 데스크톱인지, 수업 중 화면이 꺼지거나 잠자기에 들어가도록 설정돼 있는지.

## 상주 동작 ([서명 없는 최소 Electron 앱으로 상주 동작 실측](../issues/12-unsigned-app-measurement.md)에서 넘어옴)

항목과 절차는 [측정용 앱 점검 목록](12-background-probe.md)에 있다. 측정용 앱 대신 실제 앱으로 한다.

- 두 OS: 화면 잠금 · 화면 꺼짐 · 잠자기 중에 종이 울리는지, 깨어난 직후의 동작.
- 화면 꺼짐 중에 종이 안 울리는 PC라면 설정의 수업 중 화면 켜 두기를 켰을 때 울리는지. 그런 PC가 흔하면 기본값을 켬으로 바꿀지 다시 정한다([상주와 신뢰성 정책 결정](../issues/07-background-reliability-policy.md)).
- 두 OS: 방치했을 때 수업 구간 동안 잠자기에 들어가지 않는지, 마지막 수업이 끝난 뒤에는 평소대로 잠드는지.
- 두 OS: 로그인 뒤 앱이 저절로 떠 있는지.
- Windows: 트레이 아이콘이 바로 보이는지, 숨겨진 아이콘 안에 들어가는지.

## 설치 ([서명 없는 빌드 산출물의 설치 실측](../issues/14-unsigned-build-install-measurement.md)에서 넘어옴)

- Windows: 설치 파일 실행 시 SmartScreen 경고 문구와 통과 절차, 설치 후 실행 여부. Smart App Control이 켜진 PC에서의 차단 화면.
- 다른 Mac에서 내려받아 열 때의 경고와 여는 절차.
- Mac: 내려받은 앱을 열어 "열지 않음" 경고가 뜬 뒤 시스템 설정 > 개인정보 보호 및 보안의 Open Anyway(그래도 열기)로 실제로 열리는지, 그 뒤로는 경고 없이 열리는지.
- Windows: Apple Silicon에서 베타 NSIS 툴셋으로 만든 설치 파일이 정상적으로 설치 · 제거되는지.

## 업데이트와 내려받기 ([배포와 설치 방식 결정](../issues/11-distribution-decision.md)에서 넘어옴)

- Windows: 설정 화면에서 업데이트를 승인했을 때 설치와 다시 실행이 끝까지 되는지, 그 과정에서 SmartScreen이나 Smart App Control 화면이 뜨는지.
- Mac: 설정 화면에서 업데이트를 승인했을 때 끌어다 놓기 없이 교체되고 다시 실행되는지, Gatekeeper 경고나 암호 요청이 뜨는지, 로그인 항목이 유지되는지.
- 두 OS: 업데이트 뒤에도 시간표와 설정이 그대로인지.
- 실제 브라우저(Edge, Chrome, Safari)에서 다운로드 버튼을 눌렀을 때 페이지가 남고 내려받기만 시작되는지.
- 첫 릴리스 전: 릴리스를 사전 릴리스로 바꾸면 고정 내려받기 주소와 앱의 업데이트 확인이 바로 이전 버전을 가리키는지.

## 저장과 삭제 ([저장 방식과 백업 결정](../issues/17-storage-and-backup.md)에서 넘어옴)

- Windows: 앱을 제거할 때 "저장한 시간표와 종소리도 지울까요?"가 뜨는지, "아니요"면 다시 설치했을 때 시간표와 등록 음원이 돌아오는지, "예"면 데이터 폴더와 업데이트 파일이 사라지는지.
- Windows: 제거한 뒤 로그인 시 자동 실행 등록이 남지 않는지. 앱 내 업데이트 중에는 질문이 뜨지 않는지.
- 두 OS: 설정 화면의 "모든 데이터 지우기" 뒤에 데이터 폴더와 로그인 시 자동 실행 등록이 사라지는지.

## 현장

- 실습실에서 PC 스피커의 종이 드라이기 소음 속에서도 들리는지.

## 돌아다니는 강아지 ([강아지 연출의 범위와 동작 결정](../issues/09-roaming-dog-behavior.md)에서 넘어옴)

- Windows: 강아지 주변의 투명 배경이 검게 나오지 않는지. 학원 PC에서 검게 나오면 돌아다니는 강아지의 기본값을 다시 정한다.
- Windows: 강아지가 포커스를 뺏지 않고 작업 표시줄 바로 위에 항상 보이는지, 전체 화면 앱(영상, 발표 자료) 위에서 어떻게 보이는지.
- Windows: 강아지가 없는 자리는 평소처럼 눌리는지, 강아지 근처에서 커서가 깜빡이지 않는지.
- 두 OS: 강아지를 눌렀을 때의 하트, 끌어 놓았을 때의 낙하산, 종이 울릴 때 눌러서 멈추기가 되는지.
- 두 OS: 수업 시간 내내 켜 두었을 때 PC가 느려지거나 팬이 도는지.
- 두 OS: 모니터가 두 대일 때 주 모니터에서만 돌아다니는지.
- 수업 중 화면에 강아지가 돌아다니는 것이 실제 수업에 방해가 되는지.

[돌아다니는 강아지 창을 Mac에서 검증하기](../issues/28-roaming-dog-window-verification.md)에서 넘어온 것:

- 두 OS: 걷기 초당 24번 · 멈춤 초당 4번으로 그린 움직임이 어색하지 않은지. 어색하면 프레임 수를 다시 정한다(기준은 수업 시간 10분 평균 한 코어의 5% 이하).
- 두 OS: 낙하산으로 내려오는 강아지를 다시 잡을 수 있는지. 커서를 강아지에 올리자마자 눌러도 강아지가 눌리는지.
- 두 OS: 강아지 바로 옆(창의 투명한 여백)을 누르면 밑의 앱이 눌리는지.
- 두 OS: 화면을 잠그거나 화면이 꺼진 동안 강아지가 멈추고 CPU 사용량이 떨어지는지.
- Windows: 강아지를 눌러도 쓰던 앱의 포커스가 유지되는지(Mac은 딩동댕이 맨 앞 앱이 되는 것을 감수하기로 했다).
- Mac: Dock이 항상 보이는 설정에서 강아지가 Dock 바로 위에 서는지, Dock 자동 숨김에서 Dock이 올라올 때 강아지가 아이콘을 가려 불편한지.
- 두 OS: 강아지 키를 160으로 키우거나 통통 튀는 테마로 바꿨을 때 PC가 느려지지 않는지.

## 아이콘 ([앱 아이콘 시안 비교와 확정](../issues/19-app-icon-selection.md)에서 넘어옴)

- Windows: 작업 표시줄과 시작 메뉴에서 둥근 타일 아이콘이 밝은 · 어두운 테마 모두에서 또렷한지.
- Windows: 트레이의 색 아이콘이 16px에서 알아볼 수 있는지, 오늘만 끄기의 회색 + 빗금 상태가 켜진 상태와 구분되는지.
- Mac: Dock 아이콘에 시스템 틀이 제대로 씌워지는지, 메뉴 막대 기호가 밝은 · 어두운 막대에서 자동으로 뒤집히고 빗금 상태가 구분되는지.

## 화면 ([디자인 계약 확정](../issues/10-design-contract.md)에서 넘어옴)

- 두 OS: 마우스 없이 키보드만으로 시간표를 만들고, 종소리를 고르고, 설정을 바꿀 수 있는지. 초점 테두리가 어디서나 보이는지.
- 두 OS: 화면 읽기 프로그램(내레이터, VoiceOver)이 아이콘만 있는 단추의 이름과 스위치의 상태를 읽는지.
- 창을 키우거나 최소 크기로 줄였을 때 글자나 단추가 잘리지 않는지.
- Windows: Jua와 대체 글꼴(Malgun Gothic)이 섞여 보이는 곳이 어색하지 않은지, 목록의 스크롤 막대 모양.
- "되돌리기" 알림이 종 화면의 전체 음량을 가리는 것이 불편한지. 불편하면 알림의 자리를 다시 정한다.
- OS의 동작 줄이기를 켰을 때 창 안의 강아지가 멈추는지.

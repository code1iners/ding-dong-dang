# 41: 자동 시작

**What to build:** PC를 켜면 앱이 저절로 떠서 창 없이 트레이 · 메뉴 막대에 머문다. 등록에 실패하면 설정 화면에서 알 수 있다. [스펙](../spec.md)의 "상주"와 `DESIGN.md`의 "설정" 규칙을 따른다. 배경은 [상주와 신뢰성 정책 결정](07-background-reliability-policy.md)과 [서명 없는 최소 Electron 앱으로 상주 동작 실측](12-unsigned-app-measurement.md)이다.

- [x] 설정 화면은 OS에 물은 실제 등록 상태로 실패를 판단하고, 실패면 그 줄에 "등록하지 못했어요"와 "자동 시작 등록 방법" 링크를 보여 준다.
- [x] 자동 시작으로 떴을 때는 창을 열지 않는다. 직접 실행했을 때만 창을 연다. 구분하는 방법을 OS별로 확인해 티켓에 적는다. macOS에서 구분할 수 없으면 멈추고 사용자에게 확인한다. (확인: Windows는 `--auto-start` 인자, macOS는 `wasOpenedAtLogin` — 직접 실행 false 확인 / 실제 로그아웃·로그인 때 true가 되어 창 없이 뜨는지는 최종 수동 점검으로 이월, 창이 뜨면 그때 방법을 다시 정한다)
- [x] `--data-dir`로 띄운 테스트 실행은 OS의 자동 시작 등록을 건드리지 않는다.
- [x] 에이전트가 이 Mac에서 패키징한 앱으로 등록과 해제가 OS에 반영되는지 확인하고, 끝난 뒤 등록을 지운다. 로그아웃 뒤 실제로 뜨는지는 확인하지 않는다.
- [x] 등록 상태에 따른 설정 줄의 세 모습(켬, 끔, 실패)이 테스트로 확인된다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

## Comments

### 2026-11-18 구현 기록

- **구현**: `src/main/auto-start.ts`(등록 판정 · 자동 시작 구분 · 어댑터 · 시작 시 맞춤), `index.ts` 연결, `set-auto-start` · `open-auto-start-help` 명령, 설정 화면의 "컴퓨터를 켜면 자동 시작" 줄(켬 · 끔 · 실패).
- **실패 판단**: 스위치 값이 아니라 OS의 답으로 한다. macOS는 `status === 'enabled'`만 등록으로 보고(`requires-approval` · `not-found`는 실패), Windows는 `openAtLogin && executableWillLaunchAtLogin`이다. 실패는 "설정은 켬 + OS 미등록"이고 스위치는 꺼진 채 느낌표 + "등록하지 못했어요" + "자동 시작 등록 방법" 링크가 나온다. 실패 줄에서 스위치를 누르면 다시 등록을 시도한다. 창이 앞으로 올 때마다 OS에 다시 묻는다.
- **등록 시점**: 설정이 켬이고 저장 파일이 없는 처음 실행에만 등록한다(사용자가 시스템 설정에서 지운 것을 조용히 되살리지 않는다). 설정이 꺼져 있는데 등록이 남아 있으면 시작할 때 지운다.
- **자동 시작 구분(OS별)**: Windows는 등록할 때 넣는 실행 인자 `--auto-start`(등록과 조회에 같은 인자를 넘긴다). macOS 13 이후의 메인 앱 로그인 항목은 인자를 넣을 수 없어 `app.getLoginItemSettings().wasOpenedAtLogin`을 쓴다(앱 창을 만들기 전에 읽는다). 실행 인자 `--auto-start`는 모든 OS에서 자동 시작으로 읽어, 자동 검증이 같은 길을 탄다. 자동 시작이면 앱 창을 만들지 않고 트레이만 만들며 macOS는 Dock 아이콘을 숨긴다. 두 번째 실행 · Dock 클릭 · 트레이 메뉴는 창을 연다.
- **`--data-dir` · 개발 실행**: `--data-dir`가 있거나 패키징하지 않은 실행은 OS에 닿지 않는 부품(`inertLoginItem`)을 쓴다. e2e로 확인했다.
- **패키징 실측(이 Mac, macOS 27.2.1 arm64)**: `electron-packager`로 만든 앱(`/tmp`, 격리한 홈 `CFFIXED_USER_HOME`)을 실행해 처음 실행에 `status: enabled`로 등록되고, 설정 스위치로 끄면 `not-registered`, 켜면 `enabled`, 끄고 닫으면 `not-registered`로 OS에 반영됐다. 끝난 뒤 등록은 지운 상태다. 직접 실행에서 `wasOpenedAtLogin`은 false였다.
- **자동화 검증**: 타입 검사 · 린트 · 단위 253개 · e2e 63개 통과. 설정 줄 세 모습은 `SettingsScreen.test.tsx`, 창 없이 뜨기 · 저장 · 비접촉은 `e2e/auto-start.spec.ts`.
- **지금 화면 단추**: 승인 시안의 초록 바탕과 글자 색 3px 선택 테두리가 이미 코드에 있어 건드리지 않았다.

### 남은 확인 (사용자 조작 필요, 최종 수동 점검으로 이월)

macOS에서 "로그인 때 자동으로 열렸다"는 `wasOpenedAtLogin === true`는 실제 로그인 없이는 만들 수 없어 에이전트가 확인하지 못했다(직접 실행 → false만 확인). 수동 통합 테스트에서 아래를 확인한다.
1. 패키징한 앱을 실행해 설정의 자동 시작이 켜진 것을 본다(시스템 설정 > 일반 > 로그인 항목에 "딩동댕"이 보여야 한다).
2. 로그아웃했다가 다시 로그인한다. 창 없이 메뉴 막대 아이콘만 떠 있으면 구분이 된 것이다. 창이 뜨면 macOS에서 구분되지 않는 것이므로 멈추고 방법을 다시 정한다(`--auto-start`를 못 넣는 메인 앱 로그인 항목 대신 LaunchAgent 등).

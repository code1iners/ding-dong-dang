# 상주와 신뢰성 정책 결정

Type: grilling
Status: resolved
Blocked by: 01, 12

## Question

종을 놓치지 않기 위해 앱은 어떻게 상주하고, 놓쳤을 때 어떻게 하는가?

- 로그인 시 자동 실행을 기본으로 켤지, 설정으로 둘지.
- 창을 닫으면 트레이/메뉴 막대로 숨는지, 완전 종료는 어디서 하는지.
- PC가 잠자기에서 깨어났을 때 지나간 종을 울릴지 버릴지.
- 수업 시간 중 잠자기를 막을지.
- 앱이 꺼져 있었거나 종을 울리지 못했을 때 사용자에게 알리는지.
- 학원 PC가 노트북인지, 수업 중 화면이 꺼지거나 잠자기에 들어가는지는 확인하지 않았다. 그럴 수 있다고 가정하고 정한다. 화면 잠금 · 화면 꺼짐 · 잠자기 중에 종이 울리는지도 미확인이다([서명 없는 최소 Electron 앱으로 상주 동작 실측](12-unsigned-app-measurement.md)).
- 시스템이 음소거이거나 음량이 0일 때 앱이 감지해 경고할 수 있는지, 경고한다면 어떻게 하는지([종소리 정책 결정](06-bell-policy.md)에서 넘어왔다. 감지 가능 여부는 사실 확인이 필요하다).

## Answer

그릴링 대화에서 사용자가 확정한 내용이다(2026-11-16).

전제(조사 · 실측에서 나온 사실): 잠든 PC에서는 종을 울릴 수 없고 앱이 PC를 깨울 수도 없다. 앱이 막을 수 있는 것은 방치로 인한 잠자기뿐이고 덮개 닫기 · 수동 잠자기는 막지 못한다. Windows 노트북이 배터리로 돌 때는 화면이 꺼진 뒤 5분까지만 막을 수 있다. 화면 잠금 · 화면 꺼짐 중에 종이 울리는지는 미확인이라 안 울릴 수 있다고 가정했다.

자동 실행:

- 로그인 시 자동 실행은 설치 후 처음부터 켜져 있고 설정에서 끌 수 있다.
- macOS에서 등록이 실패하면 설정 화면의 그 항목에 실패를 표시하고, 수동 등록 방법은 안내문에 넣는다.
- 자동 실행으로 떴을 때는 창 없이 트레이 · 메뉴 막대에만 나타난다. 사용자가 직접 실행했을 때만 창을 연다.

창 닫기와 종료:

- 창의 닫기 버튼은 기본적으로 앱을 끝내지 않고 트레이 · 메뉴 막대로 숨긴다. 이 동작은 설정에서 바꿀 수 있다(끄면 닫기 버튼이 앱을 종료한다).
- 완전 종료는 트레이 · 메뉴 막대 메뉴의 "딩동댕 종료"로 한다(macOS는 Cmd+Q 포함). 종료할 때 확인은 묻지 않는다.
- macOS에서는 창이 닫힌 동안 Dock 아이콘을 숨긴다.
- 창을 처음 닫아 숨길 때 한 번만 "딩동댕은 계속 켜져 있어요"를 알린다. 모양은 [디자인 계약 확정](10-design-contract.md)에서 정한다.
- 이미 떠 있는 상태에서 다시 실행하면 새로 띄우지 않고 기존 앱의 창을 연다.

잠자기와 화면:

- 오늘 첫 수업 시작부터 마지막 수업 끝까지는 방치로 인한 잠자기를 막는다. 시간표 밖, 배정 없는 요일, 오늘만 끄기 중에는 막지 않는다. 설정 항목이 아니고 항상 동작한다.
- 화면 꺼짐은 기본적으로 막지 않는다. 설정에서 켜면 같은 구간 동안 화면 꺼짐도 막는다(기본 꺼짐). 화면이 꺼지면 종이 안 울리는 PC인지는 구현 뒤 점검 목록에서 확인하고, 그렇다면 이 설정을 켜도록 안내하거나 기본값을 바꾼다.

늦은 종과 놓친 종:

- PC가 깨어났거나 멈췄다 풀렸을 때 종 시각이 이미 지났으면, 1분 이내로 지난 종만 울리고 그보다 늦은 종은 버린다. 여러 개가 밀려 있으면 가장 최근 것 하나만 따진다.
- 놓친 종은 사용자에게 따로 알리지 않는다. 현황 화면만 지금 교시에 맞게 바로잡는다. 안내문에 "덮개를 닫으면 종이 울리지 않아요"를 넣는다.

여러 날 쉴 때:

- 전체 끄기는 되살리지 않는다. 길게 쉴 때는 설정에서 자동 실행을 끄고 앱을 종료한다. 쉬는 중에 PC를 켜서 앱이 떴다면 오늘만 끄기로 그날을 넘긴다.

음소거 경고:

- 시스템 음소거 · 음량 0 경고는 v1에 넣지 않는다. 안내문에 "종이 안 들리면 PC 음량과 스피커 전원을 확인하세요"를 넣고, 음원 목록의 미리 듣기를 소리 확인 수단으로 쓴다.
- 근거(서브에이전트 조사, 2026-11-16): Electron · 웹 API로는 시스템 음소거를 읽을 수 없다. macOS는 `osascript -e 'get volume settings'`로 약 0.1초에 읽힌다(이 Mac 실측). Windows는 동봉 exe나 PowerShell `Add-Type`이 필요하고 둘 다 Smart App Control · 백신에 걸릴 수 있으며 실기기에서 확인하지 못했다. 스피커 전원 · 물리 볼륨과 Windows 앱별 음소거는 어느 쪽도 감지하지 못한다.

이 티켓에서 나온 설정 항목: 로그인 시 자동 실행(기본 켬), 닫기 버튼으로 트레이에 숨기기(기본 켬), 수업 중 화면 켜 두기(기본 끔).

글로서리에 늦은 종을 추가했다.

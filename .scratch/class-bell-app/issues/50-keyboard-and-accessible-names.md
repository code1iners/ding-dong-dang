# 50: 키보드 조작과 화면 읽기 이름 점검

**What to build:** 마우스 없이 키보드만으로 시간표를 만들고, 종소리를 고르고, 설정을 바꿀 수 있다. 아이콘만 있는 단추와 스위치가 화면 읽기 프로그램에 이름과 상태를 알린다. `DESIGN.md`의 "선택과 초점", "글", "색", "움직임" 규칙을 앱 전체에서 점검하고 어긋난 곳을 고친다.

Blocked by: 36, 37, 38, 43, 45, 47

Status: resolved

- [x] 실제 앱 테스트(키보드만): 시간표를 만들고 수업 시간을 더해 저장한다, 요일에 배정한다, 시작종을 바꾼다, 설정의 스위치와 슬라이더를 바꾼다, 모달을 Esc로 닫는다.
- [x] 모든 화면과 모달에서 초점이 보이고(`초점` 색 3px, 아래 띠가 있는 단추는 띠까지), 모달이 열리면 초점이 모달 안에 머물며, 닫히면 연 곳으로 돌아간다.
- [x] 아이콘만 있는 단추마다 대상을 포함한 이름이 있고("3교시 지우기") 마우스를 올리면 이름이 뜬다. 스위치는 켜짐 · 꺼짐을, 선택 동그라미는 선택 여부를 알린다. 알림은 화면 읽기 프로그램에 읽힌다. 접근성 트리를 읽는 테스트로 확인한다.
- [x] `DESIGN.md`의 색 쌍 대비를 계산하는 검사가 통과한다(글자 4.5:1, 부품의 경계와 아이콘 3:1, 현황의 초록 고리와 흰 바탕은 예외).
- [x] OS의 동작 줄이기를 흉내 낸 상태에서 창 안의 강아지가 멈추고 모달과 알림이 움직임 없이 나타난다.
- [x] 창을 최소 크기(920×580)와 큰 크기로 띄운 캡처에서 글자와 단추가 잘리지 않는다. 에이전트가 화면별로 보고 결과를 티켓에 적는다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

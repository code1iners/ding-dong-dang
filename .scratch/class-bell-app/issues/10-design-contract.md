## Answer

디자인 계약을 루트 [`DESIGN.md`](../../../DESIGN.md)로 고정했다. 사용자가 [디자인 계약 시안](../assets/10-design-contract.html)을 보고 Q1~Q14에 모두 동의했고, 화면 전체 점검에서 나온 15건을 반영한 뒤 초점 테두리를 한 번 더 고쳐 확인했다(2026-11-17). 값과 규칙은 `DESIGN.md`에만 적고 여기서는 되풀이하지 않는다.

정한 것:

- 색, 글꼴, 글자 크기 여섯 단계, 모서리와 여백, 부품(단추, 스위치, 슬라이더, 입력 칸, 모달, 알림, 발바닥 도장)의 규칙.
- 글자로 쓰는 것과 아이콘만 쓰는 것의 기준, 말투, 화면에서 쓰는 말.
- 종소리를 고르고 등록하는 화면은 왼쪽 세로 줄의 네 번째 단추 "종"으로 따로 둔다.
- 설정 화면의 항목과 순서: 강아지 테마, 돌아다니는 강아지(크기 슬라이더와 스위치), 컴퓨터를 켜면 자동 시작, 닫으면 숨기기, 수업 중 화면 켜 두기, 버전, 모든 데이터. 전체 음량과 종소리 목록은 종 화면에 있다.
- 현황 화면의 여섯 상태, 시간표 편집의 저장 · 오류 · 나가기 확인, 처음 닫을 때 안내, 트레이 · 메뉴 막대 메뉴.
- 창은 최소 920×580에 크기 조절 가능, 밝은 화면 하나.
- 창 안 강아지가 나오는 자리와 동작 줄이기 때의 규칙.

이 티켓에서 바뀐 앞선 결정:

- [디자인 시안 비교와 방향 선택](08-design-mockups.md): 시간표 색 여덟을 새 값으로 바꿨다. 초록 단추와 요일 동그라미 위의 글자는 흰색이 아니라 짙은 색이다. 시간표 편집 화면에 "되돌리기"와 "저장"이 생겼다. 왼쪽 세로 줄의 단추는 넷이다.
- [배포와 설치 방식 결정](11-distribution-decision.md): 업데이트 화면의 흐름은 그대로이고 색과 부품은 `DESIGN.md`를 따른다(단추 글자색, 알림의 테두리).
- [시간표 모델 결정](05-timetable-model.md): 요일에 배정되지 않은 시간표는 확인 없이 지우고 알림에서 되돌린다. 배정된 시간표의 확인 모달은 그대로다.
- [종소리 정책 결정](06-bell-policy.md): 등록 음원을 지우면 알림에서 되돌릴 수 있다. 화면에서는 음원을 "종소리"라고 쓴다.
- [상주와 신뢰성 정책 결정](07-background-reliability-policy.md)의 "오늘 종 끄기" 메뉴 항목 이름은 "오늘 종"(체크 = 울림)이다.

글로서리: **음원**에 화면 표기 "종소리"를 덧붙였다. ADR은 만들지 않았다(되돌리기 어려운 결정이 없다).

검증(에이전트):

- 시안의 스물일곱 상태가 헤드리스 Chrome에서 모두 렌더되는 것을 확인했고 열네 장을 눈으로 봤다.
- 색 쌍의 대비를 WCAG 식으로 계산했다. `DESIGN.md`의 글자 쌍은 4.5:1 이상, 부품의 경계는 3:1 이상이다. 현황의 초록 고리와 흰 바탕(1.9:1)은 예외로 두었다. 같은 정보를 숫자가 말한다.
- Jua의 숫자 폭이 서로 다르고 `tabular-nums`가 듣지 않는 것, 드문 한글과 기호가 다른 글꼴로 나오는 것을 브라우저에서 측정했다.

확인하지 못한 것은 [구현 뒤 점검 목록](../checklists/post-implementation.md)으로 넘겼다: 키보드만으로의 조작과 화면 읽기 프로그램, 창 크기를 바꿨을 때의 배치, Windows에서의 글꼴과 스크롤 막대, 되돌리기 알림이 종 화면의 전체 음량을 가리는 것이 불편한지.

# 32: 종 판정과 시간표 검증

**What to build:** 종을 울릴지, 지금이 어떤 상태인지, 잠자기를 막아야 하는지를 시각을 값으로 받아 정하는 순수 함수와, 시간표의 잘못된 수업 시간을 줄별로 찾아내는 순수 함수. [스펙](../spec.md)의 "종 판정 규칙", "현황 계산", "시간표와 요일 배정"의 검증 규칙을 따른다.

## Comments

### 2026-11-17 구현 결과

- 파일: `src/shared/bell-decision.ts`(`decideBell`), `src/shared/timetable-validation.ts`(`validatePeriods`)와 각 `.test.ts`. 두 모듈은 메인과 화면이 함께 쓰도록 `src/shared/`에 두었다.
- `decideBell` 입력은 `{ timetables, weekdays, bellsOffDate, lastChecked, now }`(시각은 에포크 ms), 출력은 `{ bell: 'none'|'start'|'end', status, keepAwake }`다. 현황은 `{ kind(여섯 상태), periodNumber, periodCount, nextBell: {kind, at}|null, segment: {start, end}|null }`.
- 현황 값의 해석(스펙이 정하지 않아 정함): `periodNumber`는 수업 중에만 값이 있다. `nextBell`은 같은 시각의 끝종을 뺀 다음 종이라서 이어지는 수업 중에는 다음 시작종이다. `segment`는 수업 중(그 수업의 시작~끝)과 쉬는 시간(방금 끝난 수업의 끝~다음 수업의 시작)에만 있다. 요일에 배정된 시간표 id가 목록에 없으면 수업 없는 날로 본다.
- `validatePeriods(periods)`는 `{ index(0부터), rule, message }` 목록을 돌려준다. 규칙은 시각 범위(00:00~23:59), 끝이 시작보다 늦음, 겹침, 12시간 이하다. 겹침은 겹친 두 줄에 모두 달고 서로의 시각을 문구에 넣는다. 12시간 초과는 가장 늦게 끝나는 줄에 단다. 시각이 잘못된 줄은 겹침·길이 검사에서 뺀다.
- 해석: 티켓의 "끝과 시작이 같은 경우는 통과"는 앞 수업의 끝 = 다음 수업의 시작으로 읽었다. 한 수업의 시작 = 끝은 "끝은 시작보다 늦어야 한다"에 따라 실패다(스펙이 우선).
- 시나리오 표 22줄이 모두 테스트에 있다(9·10은 한 테스트). 여섯 상태마다 테스트가 있고 시간대(UTC, Asia/Seoul, America/Los_Angeles)를 바꿔도 통과한다.
- 검증: `npm run check`(타입 검사, 린트, Vitest 66개, Playwright 7개) 통과. 구현을 일부러 깨뜨리는 변이 검사로 60초 경계, 가장 최근 종 선택, 어제 날짜의 종, 끈 날짜, 정렬, 수업 끝 경계, 12시간 경계, 겹침 등호, 범위 상한, 오류 순서가 실제로 테스트에 잡히는 것을 확인했다. "같은 시각의 끝종 제거"는 안정 정렬 때문에 결과가 달라지지 않는 동등 변이라 테스트로 잡지 않았다.
- 코드 리뷰(Standards·Spec 두 축) 반영: 주석 보강, `minuteOfDay`→`atMinuteOfDay`, 검증 안의 `sound`→`checked`, 규칙 순서 상수에서 `PeriodRule` 파생. Spec 축 지적은 없었다. 시간표 이름 비우기 금지는 이 티켓의 검증 규칙 밖이라 넣지 않았다.

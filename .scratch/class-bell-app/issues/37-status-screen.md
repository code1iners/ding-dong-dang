# 37: 현황 화면

**What to build:** 창을 열면 지금 교시와 다음 종까지 남은 시간이 고리, 숫자, 발바닥 도장으로 보이고, "오늘 종" 스위치로 오늘 남은 종을 끈다. [스펙](../spec.md)의 "현황 계산", "화면"과 `DESIGN.md`의 "현황" 표를 따른다.

Blocked by: 34

Status: resolved

- [x] 창을 열면 현황 화면이다. `DESIGN.md`의 여섯 상태가 고리, 글, 발바닥 도장으로 그려진다. 고리 안 강아지의 자리는 비워 둔다([강아지 그리기와 고리 안 강아지](42-dog-rendering-ring-dog.md)에서 채운다).
- [x] 고리가 지금 구간의 남은 시간만큼 줄어들고 남은 시간이 초마다 바뀐다. 한 시간이 넘으면 "시:분:초"로 쓴다. 숫자는 자리마다 같은 폭의 칸에 들어가 흔들리지 않는다.
- [x] 발바닥 도장이 지난 교시, 지금 교시, 남은 교시를 모양으로 구분한다.
- [x] "오늘 종" 스위치를 끄면 끈 날짜가 저장되고 울리던 종이 멈춘다. 다시 켜면 풀린다. 꺼진 동안에도 현황은 시간표대로 나온다.
- [x] 시간표가 하나도 없으면 "시간표를 만들어 주세요"와 "시간표 만들기" 단추가 나오고, 누르면 시간표 화면으로 간다.
- [x] 실제 앱 테스트: 오늘 요일과 지금 시각에 맞춰 만든 저장 파일로 여섯 상태가 각각 맞게 나온다. 스위치를 끄고 앱을 다시 띄우면 꺼진 상태가 유지되고, 끈 날짜가 어제인 파일로 띄우면 켜져 있다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

## Comments

- 사용자 결정 반영 확인: 왼쪽 세로 줄 "지금 화면" 단추의 초록 바탕과 글자 색 3px 선택 테두리는 이미 코드(`app.css`의 `.rail-button[aria-current='page']`)와 e2e(`app-shell.spec.ts`)에 있어 건드리지 않았다.
- 구현: `BellStatus`에 `periodsDone`(끝난 교시 수)을 더했다(쉬는 시간의 "지난 교시" 도장을 위해). 현황은 렌더러가 `decideBell`로 매초 계산한다(`AppState.bellsOffDate` 추가, `set-bells-off` 명령). 표시 계산은 `shared/status-view.ts`(남은 시간 글, 고리 비율, 도장 상태)에 순수 함수로 두었다.
- 판단: 수업이 이어져 다음 종이 시작종이어도 DESIGN.md 표대로 수업 중 글은 "끝종까지"다(코드 리뷰에서 잡아 고침). 시간표가 하나도 없을 때는 시안대로 "오늘 종" 스위치를 그리지 않는다.
- 판단: 왼쪽 세로 줄 위로 현황 영역이 겹치므로 `.rail`에 `z-index`를 줬다(안 주면 세로 줄 클릭이 막혔다).
- 시험: Electron 창에는 Playwright `clock`이 닿지 않아 e2e는 화면의 `Date.now`를 옮겨 여섯 상태를 확인했다. 오늘 종을 끄면 울리던 종이 멈추는 동작은 스케줄러 단위 시험(`scheduler.test.ts`)이 맡고, 실제 소리 확인은 하지 않았다.
- 검증: typecheck, lint, vitest 195개, e2e(status 9개 포함 전체) 통과.

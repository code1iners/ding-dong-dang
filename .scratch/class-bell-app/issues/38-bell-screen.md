# 38: 종 화면

**What to build:** 종 화면에서 전체 음량을 조절하고, 종소리를 미리 듣고, 시작종과 끝종을 고르고, 자기 파일을 종소리로 등록한다. [스펙](../spec.md)의 "음원", "종 재생"과 `DESIGN.md`의 "종" 화면 규칙을 따른다.

## Comments

2026-11-17 구현 기록.

- 화면은 `src/renderer/src/BellScreen.tsx`(목록, 이름 바꾸기, 지우기·되돌리기 알림)와 `Slider.tsx`다. 시작종 · 끝종 동그라미는 `aria-pressed` 단추이고, 체크 아이콘이 있어 색으로만 구분하지 않는다.
- 저장 데이터를 바꾸는 순수 함수는 `src/shared/sound-ops.ts`(등록, 이름, 지우기·되돌리기, 음량, 선택, 시작할 때 빼기)이고 테스트가 있다. 지우기는 시작종 · 끝종을 웨스트민스터로 돌리고 되돌리기는 자리 · 음량 · 선택을 함께 되살린다.
- 등록은 메인이 파일 고르기 창을 열고(`register-sound`), 숨긴 재생기 창에 파일 내용을 보내 길이와 재생 가능 여부를 확인한다(`probe`). 확인과 복사는 `src/main/sound-files.ts`(60초 + 0.1초 허용, 64MB 넘는 파일은 긴 파일로 거절)다. 복사 파일 이름은 `<id>.<확장자>`로 겹침을 피하고 목록 이름은 확장자를 뺀 원래 이름이다.
- 복사해 둔 파일은 알림이 닫히거나(×, 다른 일을 해서 알림이 사라짐) 앱이 다시 시작할 때 `sounds/`의 안 쓰이는 파일을 정리하며 지워진다. 되돌릴 수 있는 다른 지운 음원과 등록 중인 파일은 정리에서 뺀다(코드 리뷰에서 나온 경합을 고치고 e2e로 확인).
- 시작할 때: 파일이 없는 등록 음원은 바로, 재생할 수 없는 것은 숨긴 창이 뜬 뒤 알리지 않고 목록에서 뺀다. 재생기가 답하지 못한 경우(응답 없음 · 창 죽음)나 읽기 실패는 파일 탓으로 보지 않고 둔다.
- 미리 듣기는 숨긴 창의 같은 재생기를 쓰고 실제 종과 같은 크기(음원 음량 × 전체 음량)다. 종 시각이 오면 `ring()`이 미리 듣기를 끊는다. 종이 울리는 중에 누른 미리 듣기는 무시한다(스펙에 없는 판단). 앱 상태에 `sounds`, `soundVolumes`, `startBell`, `endBell`, `masterVolume`, `previewingSound`가 더해졌고 `CommandResult`에 `message`, `name`이 생겼다.
- 슬라이더 채움은 한 색만 쓰는 `linear-gradient` 한 겹으로 그렸다(보이는 그라데이션 아님). 길 모서리 5px은 DESIGN.md 목록에 없지만 높이 10의 원통 모양이라 시안(`.sl`)을 따랐다.
- 실제 앱 테스트는 `e2e/bell-screen.spec.ts`(12개): 등록 → 시작종 선택 → 지우기 → 되돌리기, 61초 거절, 60초 허용, 재생할 수 없는 파일 거절, `sounds/` 파일을 지우고 재시작하면 줄이 없음, 재생할 수 없는 파일은 시작 때 빠짐, 음량 · 이름 저장, 미리 듣기 토글 · 끊기 · 음량, 미리 듣는 중 실제 종 시각(최대 1분 남짓)에 종이 울림. 전체 `npm run check`(타입 검사, 린트, 단위 208개, e2e 52개) 통과.
- 사용자 결정 반영(지금 화면 단추의 선택 테두리): 33번에서 이미 들어 있고 e2e로 확인되어 건드리지 않았다.
- 사용자 조작이 필요한 것: 실제 소리를 귀로 듣는 확인(미리 듣기 크기가 실제 종과 같은지 체감)은 하지 못했다. 수동 통합 테스트에서 확인해야 한다. 파일 고르기 창은 e2e에서 `dialog.showOpenDialog`를 대체했으므로 실제 OS 창에서 파일을 고르는 것도 수동 통합 테스트 몫이다. mp3 · m4a · ogg는 실제 파일로 확인하지 못하고 wav와 깨진 mp3만 확인했다.

# 36: 수업 시간 편집과 저장

**What to build:** 시간표의 수업 시간을 더하고, 고치고, 지우고, 12시간 시계판에서 호로 본다. 잘못된 시각은 그 줄에 표시되고 저장이 막힌다. [스펙](../spec.md)의 "시간표와 요일 배정", "화면"과 `DESIGN.md`의 "시간표" 화면 규칙을 따른다.

Blocked by: 32, 35

Status: resolved

- [x] 오른쪽 카드에 교시별 시작 · 끝 시각 줄과 "수업 시간" 더하기가 있다. 교시 번호는 시작 시각 순서로 매겨진다. 시각의 숫자는 자리마다 같은 폭의 칸에 들어간다.
- [x] 왼쪽 카드의 12시간 시계판에 수업 시간이 교시 번호가 붙은 호로 나온다.
- [x] 수업 시간을 더하거나 고치거나 지우면 "되돌리기"와 "저장"이 나타난다. "되돌리기"는 마지막 저장 상태로 돌린다.
- [x] 검증 오류가 있으면 그 줄에 빨간 테두리, 아래에 느낌표와 이유 한 줄이 보이고 "저장"이 잠긴다. 자동으로 고치지 않는다.
- [x] 저장하지 않은 채 다른 화면, 다른 요일, 다른 시간표로 가거나 창을 닫으려 하면 "계속 편집", "저장 안 함", "저장" 모달이 뜬다. 오류가 있으면 모달의 "저장"도 잠긴다.
- [x] "저장"이 실패하면 편집 상태가 그대로 남고 그 자리에서 실패 알림이 뜬다.
- [x] 한 시간표를 저장하면 그 시간표를 쓰는 모든 요일이 함께 바뀐다.
- [x] 실제 앱 테스트: 수업 시간을 더해 저장하고 앱을 다시 띄우면 남아 있다. 겹치는 수업 시간에서 "저장"이 잠긴다. 저장하지 않고 다른 화면으로 가면 모달이 뜬다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

## Comments

- 구현: 순수 계산 `src/shared/period-edit.ts`(교시 번호, 새 줄 기본값, 시각 숫자 입력, 시계판 호)와 `setPeriods`(시작 시각 순 정렬 저장), 명령 `set-periods`(메인이 검증 재확인, 결과 `ok` 반환) · `set-editing-dirty` · `close-window`, 창 닫기 가로채기(`window:close-requested`), 렌더러 `TimeField` · `Dial` · 편집 초안과 떠나기 가드.
- 시각 칸은 숫자마다 같은 폭의 칸(0.62em, 쌍점 0.3em)을 그리고 실제 입력은 그 위에 투명하게 겹친 칸이 받는다. 24시 이상도 그대로 받아 검증이 그 줄에 오류로 알린다. 줄은 고치는 도중에는 움직이지 않고 초점이 목록 밖으로 나가면 시작 시각 순으로 정렬된다.
- 시간표 선택 창은 열기 전에 저장하지 않은 편집을 묻는다(선택 창 안에서 지우기·이름 바꾸기가 편집 중인 시간표에 닿지 않게). 같은 시간표를 쓰는 다른 요일로 가도 티켓대로 묻는다.
- 저장 성공 알림 "수업 시간을 저장했어요"는 추가했다(DESIGN.md 성공 알림). 실패 알림은 기존 앱 수준 `saveFailures` 알림이 그 자리에서 띄우고, 편집 상태는 그대로 남는다.
- 리뷰에서 정확히 12시간 수업 시간(검증 통과)에 호가 안 그려지는 문제를 찾아 한 바퀴 원으로 그리게 고쳤다.
- "지금 화면" 단추의 선택 표시(글자 색 3px 테두리)는 이미 코드에 있어 건드리지 않았다.
- 시안의 시계판 가운데 강아지 그림은 강아지 그림 티켓 범위라 넣지 않았다.
- 검증: 타입 검사, 린트, 단위 185개, 실제 Electron e2e 31개 통과(수업 시간 저장 후 재실행 유지, 겹침에서 저장 잠금, 다른 화면·요일·시간표·창 닫기 모달, 저장 실패 유지, 숫자 칸 폭 포함). 화면은 스크린샷으로 확인했다. 사용자 조작이 필요한 미확인 항목은 없다.

# 33: 내장 종소리 만들기

**What to build:** 내장 음원 열두 개(여섯 짝의 시작 · 끝)가 WAV 파일로 저장소에 있다. [스펙](../spec.md)의 "음원"을 따른다. 악보와 음색의 원본 값은 [종소리 청취 시안](../assets/16-bell-sounds.html)의 `SCORES`와 `TIMBRES.chime`이고, 짝과 길이는 [종소리 청취 시안과 음원 확정](16-bell-sound-selection.md)의 표다.

Blocked by: 30

Status: resolved

- [x] 스크립트 하나가 원본 값으로 파형을 계산해 열두 개의 WAV를 만든다. 브라우저 없이 돈다. 만든 파일은 저장소에 넣는다.
- [x] 음원마다 고정된 id와 화면 이름(짝 이름 "웨스트민스터", "딩동댕동", "띠링", "다섯 음", "아르페지오", "화음"에 "시작" 또는 "끝")이 있다.
- [x] 테스트가 확인한다: 열두 파일이 모두 있다, 길이가 표와 0.1초 안에서 맞는다, 어느 파일도 최대값이 1을 넘지 않는다, 파일끼리의 크기(RMS)가 정한 범위 안에 있다.
- [x] 스크립트를 다시 돌려도 저장소의 파일과 같은 결과가 나온다.
- [x] 뒤에 더한 넷(띠링, 다섯 음, 아르페지오, 화음)은 에이전트가 파형을 확인한 적이 없다. 이 티켓에서 처음 확인하고, 화음에서 찌그러짐이 나오면 음을 바꾸지 않고 크기만 줄여 맞춘다. 그것으로 안 되면 멈추고 사용자에게 확인한다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

## Comments

2026-11-17, 구현 완료.

- 스크립트: `npm run sounds` → `scripts/build-bell-sounds.mts`(악보·음색·레벨 계산은 `scripts/bell-synth.mts`, id·화면 이름·길이는 `src/shared/builtin-sounds.ts`). 결과는 `resources/sounds/builtin/*.wav` 열두 개(44.1kHz 16비트 모노).
- id는 `{westminster,four-note,tiring,five-note,arpeggio,chord}-{start,end}`. 기본값 id(`westminster-start/end`)는 `src/shared/data.ts`와 같다.
- 시안과 다른 점 두 가지: 시안의 압축기(DynamicsCompressor)와 마스터 음량 대신 파일 전체 RMS를 0.13으로 맞추는 곱셈을 쓴다. 파일 끝이 뚝 끊기지 않게 마지막 0.3초에 코사인 페이드아웃을 넣었다.
- 처음 파형을 확인한 뒤 4곡(띠링, 다섯 음, 아르페지오, 화음): 레벨 맞춤 전 최대값이 1.8~3.7까지 나오는 겹침 곡이었고(아르페지오가 가장 큼), RMS 0.13으로 곱해 맞추면 모두 최대값 0.95 이하다. 화음은 음을 바꾸지 않고 크기만 줄여 맞췄고 별도 조치는 필요 없었다. 한도를 넘으면 스크립트가 멈춰 알린다.
- 테스트(`scripts/bell-synth.test.mts`): 열두 파일 존재, 길이 ±0.1초, 최대값 ≤ 0.95, RMS ±3%, 저장소 파일과 재생성 바이트 일치. vitest 포함 범위에 `scripts/`를 더했다.
- 사용자 결정 반영: 왼쪽 세로 줄 "지금 화면" 단추에 초록 바탕을 유지한 채 글자 색 3px 테두리(3px 띄움)를 더했다(`app.css`). e2e 시험 추가.
- 사용자 조작이 필요한 것: 실제 소리를 귀로 듣는 확인은 하지 못했다. 구현 뒤 수동 통합 테스트에서 열두 음원을 들어 시안과 비슷한 소리인지, 음량이 고른지 확인해야 한다.

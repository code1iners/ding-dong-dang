# 35: 시간표 만들기와 요일 배정

**What to build:** 시간표 화면에서 시간표를 만들고, 이름을 바꾸고, 지우고, 요일마다 하나씩 배정한다. 이 티켓이 모달과 알림 부품을 처음 만든다. [스펙](../spec.md)의 "시간표와 요일 배정", "화면"과 `DESIGN.md`, [디자인 계약 시안](../assets/10-design-contract.html)을 따른다.

Blocked by: 31

Status: resolved

- [x] 시간표 화면을 열면 오늘 요일이 선택되어 있다. 요일 동그라미 일곱 개가 배정된 시간표의 색으로 보이고, 마우스를 올리면 시간표 이름이 뜬다.
- [x] 시간표 선택 입력기를 누르면 화면 가운데에 모달이 뜬다. 시간표를 고르면 선택한 요일의 배정이 바뀌고 즉시 저장된다. "없음"과 "새 시간표"는 항상 맨 아래에 보이고, 목록은 다섯 줄 반 높이에서 스크롤된다.
- [x] "새 시간표"는 이름 "새 시간표"로 만들어지고 색 여덟이 만든 순서대로 배정된다. 시간표를 지워도 남은 시간표의 색은 바뀌지 않는다.
- [x] "편집"을 누를 때만 줄마다 이름 바꾸기와 지우기가 나타나고 "완료"로 돌아간다. 빈 이름으로는 바꿀 수 없다.
- [x] 요일에 배정되지 않은 시간표는 바로 지워지고 알림의 "되돌리기"로 복구된다. 배정된 시간표는 영향받는 요일을 보여 주는 확인 모달을 거치고, 지우면 그 요일은 없음이 된다.
- [x] 모달과 알림이 `DESIGN.md`의 규칙대로다(되돌릴 수 없는 일의 기본 초점은 "취소", Esc로 닫힘, 성공 알림은 4초, 실패와 "되돌리기" 알림은 남음).
- [x] 저장 실패 알림과 "저장된 시간표를 읽지 못해 새로 시작했어요" 알림이 뜬다.
- [x] 실제 앱 테스트: 시간표를 만들어 요일에 배정하고 앱을 다시 띄우면 남아 있다. 배정 안 된 시간표를 지우고 되돌린다. 배정된 시간표를 지우면 확인 모달이 뜬다.
- [x] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

## Comments

- 2026-11-17 구현 완료. 타입 검사·린트·단위 161개·실제 앱(Playwright) 22개 통과(`npm run check`).

- 판단 기록:
  - 시간표 선택 창 폭은 시안(360)과 DESIGN.md(380)가 달라 DESIGN.md를 따랐다. 목록의 위·양옆 여백을 8로 두어 선택 테두리(3px+간격 3px)가 스크롤 영역에 잘리지 않게 했고, 보이는 높이는 다섯 줄 반(293)이다.
  - 시안의 여백 18·6·2px, 반지름 8px, 띠 색 `#c3d3e6`은 DESIGN.md의 "4의 배수 · 반지름 10/14/16/20 · 색 표" 규칙에 맞춰 바꿨다.
  - "새 시간표"는 선택 모드에서 고른 요일에 바로 배정하고 창을 닫는다(목록에서 고르는 것과 같은 동작). 편집 중에는 목록에만 더하고 창을 열어 둔다. 편집 중에는 시안대로 "없음"을 숨긴다.
  - 문구는 조사 오류를 피해 "'반이름' 시간표를 지웠어요/지울까요?"로 썼다. 되돌리면 성공 알림 "시간표를 되돌렸어요"가 뜬다(4초).
  - "되돌리기" 알림은 다른 시간표 일(고르기·만들기·지우기·이름 바꾸기·편집 전환)을 하면 닫힌다. 배정된 시간표를 확인 모달로 지울 때는 되돌리기가 없다.
  - 저장 실패 알림은 실패할 때마다 뜬다(`saveFailures` 횟수 증가). 창 위치 저장 실패는 알리지 않는다. "새로 시작했어요" 알림은 `ack-fresh-start` 명령으로 실행당 한 번만 뜨고, 문구 뒤에 "시간표를 다시 만들어 주세요."를 붙였다.
  - 지운 시간표는 메인이 실행 동안 id로 기억해 "되돌리기"에 쓴다(렌더러가 시간표 내용을 보내지 않는다).
- 이 티켓은 왼쪽 카드(선택 입력기, 요일 동그라미)까지다. 교시별 시각 줄·시계판·저장/되돌리기는 이어지는 티켓.
- 사용자 손이 필요한 확인 없음.

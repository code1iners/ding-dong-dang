# 서명 없는 최소 Electron 앱으로 상주 동작 실측

Type: task
Status: resolved
Blocked by: 

## Question

조사로 확인하지 못한 상주 동작이 서명 없는 Electron 앱에서 실제로 어떻게 되는가? 트레이 상주 + 메인 프로세스 타이머 + 숨긴 창 오디오만 가진 버리는 최소 앱을 만들어 측정하고 수치와 관찰을 기록한다. 배경은 [Electron 상주와 시각 정확도의 OS별 한계 조사](01-os-background-reliability.md)의 미확인 항목이다.

- macOS: 서명 없는 앱과 ad-hoc 서명 앱에서 로그인 항목 등록(`setLoginItemSettings`)이 성공하는지, 실패하면 대안(사용자 LaunchAgent, 수동 로그인 항목 추가)이 동작하는지.
- macOS: 창을 숨긴 채 오래 둔 뒤 메인 프로세스 타이머가 얼마나 늦는지(App Nap), `powerSaveBlocker`를 켜면 달라지는지.
- 두 OS: 화면 잠금 중과 잠자기에서 깨어난 직후에 종이 울리는지, 숨긴 창에서 오디오가 제스처 없이 재생되는지.
- Windows 11: 사용자의 개인 Windows PC에서 같은 항목과 트레이 아이콘의 기본 표시 위치, 화면이 꺼졌을 때의 동작을 측정한다. 에이전트가 그 PC에 접근할 수 없으므로 사용자가 따라 할 점검 목록을 만들어 전달한다.

## Comments

### 2026-11-16 중간 기록 (macOS에서 에이전트가 잰 것)

측정용 앱: `prototypes/bell-probe/` (Electron 45.3.3, macOS 27.2.1 arm64). 사용자가 할 측정은 [점검 목록](../checklists/12-background-probe.md)에 있다.

- **빌드의 서명 상태**: `@electron/packager`가 만든 그대로의 앱은 링커가 붙인 ad-hoc 서명(`adhoc,linker-signed`)만 있고 `codesign --verify`는 실패한다. `codesign --force --deep -s -`로 다시 서명하면 검증을 통과한다. 두 벌 모두 이 Mac에서는 실행됐다(내려받은 것처럼 격리 속성이 붙은 경우는 설치 실측 티켓에서 본다).
- **로그인 항목 등록**: 두 벌 모두 `setLoginItemSettings({ openAtLogin: true })` 뒤 `getLoginItemSettings().status`가 `not-found`에서 `enabled`로 바뀌었다. 로그인 때 실제로 뜨는지는 아직 확인하지 않았다(로그아웃 필요). 등록은 해제해 두었다.
- **숨긴 창 오디오**: `show: false` 창에서 제스처 없이 `audio.play()`가 성공했고 `ended`까지 왔다. 사람이 귀로 들은 확인은 아직 없다. 숨긴 창의 `document.visibilityState`는 `visible`로 나온다.
- **메인 타이머 지연**: Dock을 숨긴 메뉴 막대 전용 상태로 7분 30초 동안 1초 간격 틱의 최대 지연이 블로커를 켠 쪽과 끈 쪽 모두 3ms였다. App Nap으로 보이는 지연은 없었다. 다만 사용 중인 Mac(화면 켜짐, 다른 프로그램이 잠자기를 막는 중)에서 짧게 잰 것이라 오래 방치한 경우는 말해 주지 못한다.
- **부수 관찰**: 1초마다 벽시계를 확인하는 방식은 종이 예정 시각보다 0.3~0.85초 늦게 울렸다(틱이 매번 약 1.6ms씩 밀려 위상이 흘러간다). 실제 앱은 다음 종 시각에 맞춘 타이머를 따로 걸어야 한다.
- **Windows 빌드**: Apple Silicon에서 `--platform=win32 --arch=x64` 포터블 폴더가 Wine 없이 만들어졌다(`dist/BellProbe-win32-x64.zip`, 151MB). 실행 여부는 Windows PC에서 확인해야 한다.

남은 것: 점검 목록의 macOS 3항목(화면 잠금, 잠자기, 로그아웃 뒤 자동 실행)과 Windows 전체.

## Answer

Mac에서 에이전트가 잴 수 있는 것만 재고 닫는다. 사용자가 손으로 해야 하는 확인(Windows 전체, Mac의 화면 잠금 · 잠자기 · 로그아웃 뒤 자동 실행)은 **구현을 마친 뒤 수동 통합 테스트에서 한다**(2026-11-16 사용자 결정). 지금은 Windows PC가 없다.

확인된 것(수치와 조건은 위 중간 기록):

- macOS 로그인 항목 등록은 서명 없는 빌드와 ad-hoc 서명 빌드 모두 `status: enabled`를 돌려준다. 로그인 때 실제로 뜨는지는 미확인.
- 숨긴 창에서 제스처 없이 오디오가 재생된다.
- 창 없이 메뉴 막대에만 있는 앱의 메인 프로세스 타이머는 늦지 않았다(7분 30초, 최대 3ms, 블로커 유무와 무관). 사용자가 이 결과로 충분하다고 판단했다. App Nap 대책은 따로 두지 않는다.
- 1초 주기로 벽시계를 확인하면 종이 최대 1초 가까이 늦는다. 다음 종 시각에 맞춘 타이머가 필요하다.
- Apple Silicon에서 Windows x64 포터블 빌드가 Wine 없이 만들어진다.

미확인으로 남긴 것(구현 뒤 확인): 화면 잠금 · 화면 꺼짐 · 잠자기 중과 깨어난 직후의 종(두 OS), Windows 트레이 아이콘의 기본 위치, 로그인 뒤 실제 자동 실행(두 OS). 정책 결정은 이것들이 나쁜 쪽일 수 있다고 가정하고 한다. 점검 항목은 [점검 목록](../checklists/12-background-probe.md)에 있고 구현 뒤 실제 앱으로 옮겨 쓴다.

측정용 앱 `prototypes/bell-probe/`는 커밋하지 않은 채 작업 폴더에 있다. [서명 없는 빌드 산출물의 설치 실측](14-unsigned-build-install-measurement.md)이 이어서 쓴다.

### 2026-11-16 마감 점검

기준: 티켓의 검증은 에이전트가 직접 하는 것만 둔다. 사람이 하는 확인은 모든 구현이 끝난 뒤의 수동 통합 테스트뿐이다(사용자 확인).

- 항목 1 (macOS 로그인 항목): 등록 결과는 완료. 로그인 뒤 실제 실행은 로그아웃이 필요해 에이전트가 할 수 없으므로 제외하고 구현 뒤로 넘겼다. 등록이 성공으로 나와 대안 경로(LaunchAgent, 수동 등록)는 재지 않았다.
- 항목 2 (App Nap): 완료.
- 항목 3 (잠금 · 잠자기 중의 종, 숨긴 창 오디오): 오디오는 완료. 잠금 · 잠자기는 사용자의 화면을 잠그거나 Mac을 재워야 해서 에이전트가 할 수 없으므로 제외하고 구현 뒤로 넘겼다.
- 항목 4 (Windows 11): 에이전트가 접근할 Windows PC가 없어 전체를 제외하고 구현 뒤로 넘겼다. 점검 목록은 만들어 두었다.

종 간격을 15초로 바꿔 다시 만든 Mac 빌드 두 벌을 실행해 종 재생(`ok: true`)과 로그인 항목 해제(`not-registered`)를 확인했다. Windows 빌드는 실행해 보지 못했다. 에이전트가 이 티켓에서 더 할 일은 없다.

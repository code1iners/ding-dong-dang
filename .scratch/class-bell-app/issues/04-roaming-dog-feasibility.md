# 화면 바닥을 돌아다니는 강아지 연출의 구현 가능성 조사

Type: research
Status: resolved
Blocked by: 

## Question

Electron에서 강아지가 '화면 바닥'을 돌아다니는 연출을 어떻게 만들 수 있고, 방식마다 무엇이 걸리는가?

- 앱 창 안의 바닥에서만 움직이는 방식과 데스크톱 화면 전체의 바닥(작업 표시줄 · Dock 위)을 돌아다니는 투명 오버레이 창 방식을 비교한다.
- 오버레이 방식: 투명 · 항상 위 · 클릭 통과 창의 Windows 11과 macOS별 지원과 알려진 문제(전체 화면 앱, 여러 모니터, 작업 표시줄 · Dock 위치와 크기 감지).
- 계속 움직이는 애니메이션의 CPU · 배터리 부담과 줄이는 방법.
- 애니메이션 자산 형식 후보(스프라이트 시트, Lottie, Rive 등)와 필요한 동작 수.
- 비슷한 오픈소스 데스크톱 펫 구현 사례.

## Answer

조사 문서: `research/roaming-dog-feasibility` 브랜치(커밋 `c32d390`)의 `docs/research/roaming-dog-feasibility.md`.

확인 방식: 공식 문서 · 소스 · 이슈만 읽었다. 실제 기기에서 Electron을 띄워 확인한 것은 없다.

두 방식 비교:

- **창 안 바닥**: 일반 창 안의 DOM/캔버스 애니메이션만 쓰면 되고, 플랫폼 분기와 알려진 문제를 찾지 못했다. 창이 숨겨지면 애니메이션 부담이 저절로 줄어든다. 트레이 상주 앱이라 창이 닫힌 동안에는 강아지가 보이지 않는다.
- **화면 전체 오버레이**: 투명 · 항상 위 · 클릭 통과 창과 `screen.workArea`로 공식 API만으로 만들 수는 있다. 작업 표시줄 · Dock 위에 뜨려면 창 레벨이 `pop-up-menu` 이상이어야 한다.
- **오버레이의 열린 문제**: Windows 일부 기기에서 투명 배경이 검게 나오는 이슈(electron#40515, 열림), 항상 위 + 클릭 통과에서 커서가 깜빡이는 이슈(#35414, 수정 미병합), macOS 전체 화면 위 표시가 불안정한 이슈(#36364, 미해결로 닫힘).
- **전체 화면 감지**: 다른 앱이 전체 화면인지 알려 주는 Electron API를 찾지 못했다. 수업 자료 위에 강아지가 뜨면 안 된다면 시간표에 맞춰 숨기는 방법이 있다(추정).

두 방식에 공통인 사실:

- **CPU**: 다른 프로젝트의 사용자 측정으로, 자유 배회를 켜면 한 코어의 60%대, 끄면 1%대였다. 어느 방식이든 대부분의 시간을 정지 상태로 두는 행동 설계가 필요하다. 오버레이는 가려져서 멈추는 일이 없어 정지 장치를 직접 만들어야 한다.
- **전력 대응**: 배터리 사용 · 화면 잠금 · 자리 비움 때 끄는 것은 `powerMonitor`로 가능하다.
- **자산**: 동작은 최소 3~4개, 자연스러운 범위는 6~10개, 동작당 4~12프레임 · 8~10fps로 본다(추정). 스프라이트 시트나 APNG/WebP로 충분하다. Lottie · Rive 런타임은 MIT지만 Rive 무료 내보내기에는 스플래시 화면이 붙는다.
- **자산 라이선스**: 공개 저장소의 그림은 코드와 라이선스가 다르다. vscode-pets 강아지는 CC BY-ND 4.0이라 가져다 쓸 수 없다.
- **순서**: 상태 기계와 자산은 두 방식이 공유할 수 있어, 창 안 방식을 먼저 만들고 오버레이를 나중에 얹을 수 있다(추정).

미확인(실측이 필요한 것): 오버레이가 Windows 11 · macOS의 전체 화면 앱 위에서 어떻게 보이는지, 작업 표시줄 · Dock 자동 숨김일 때의 `workArea` 값, 투명 배경 검정 이슈가 대상 PC에서 재현되는지, 강아지 한 마리가 실제로 쓰는 CPU · 배터리 수치. 조사 문서 끝에 가장 싼 검증 실험(정지 이미지 하나짜리 오버레이 프로토타입)과 중단 조건이 있다.

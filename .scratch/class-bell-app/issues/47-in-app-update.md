# 47: 앱 내 업데이트

**What to build:** 새 버전이 나오면 앱이 미리 내려받아 검증하고, 설정 단추의 주황 점과 버전 줄로 알린다. 사용자가 설정 화면에서 승인하면 설치하고 다시 실행한다. [스펙](../spec.md)의 "앱 내 업데이트"와 `docs/adr/0001-in-app-update-trust.md`를 따른다. 화면은 [업데이트 화면 시안](../assets/11-update-flow.html)의 흐름에 `DESIGN.md`의 색과 부품을 적용한다. 구현 선례는 `~/workspace/work/stardraft`다.

Blocked by: 29, 37, 46

Status: ready-for-agent

- [ ] Ed25519 키 쌍을 만든다. 개인 키는 개발 Mac의 Keychain과 `/Users/wraith/workspace/keys/ding-dong-dang`에 두고 저장소에 넣지 않는다. 공개 키는 앱에 넣는다.
- [ ] 검증 함수 테스트: 맞는 서명은 통과한다, 틀린 서명 · 바뀐 안내 파일 · 서명 없는 파일은 거절한다, 서명 목록 중 하나만 맞아도 통과한다.
- [ ] electron-updater의 `github` 제공자로 `code1iners/ding-dong-dang`의 공개 릴리스를 본다. 앱이 시작할 때와 그 뒤 24시간마다 확인한다. `publisherName`은 넣지 않는다.
- [ ] 새 버전을 찾으면 묻지 않고 내려받아 검증한다. 검증에 실패하면 파일을 버리고 아무것도 보여 주지 않는다.
- [ ] 설정 화면 맨 아래 "버전" 줄: 새 버전이 없으면 지금 버전과 "최신이에요", 확인에 실패하면 "새 버전을 확인할 수 없어요"와 "다시 확인", 준비되면 새 버전 번호와 "업데이트" 단추. 준비되면 왼쪽 설정 단추에 주황 점이 붙는다.
- [ ] "업데이트"를 누르면 확인 모달(강아지, "업데이트할까요?", 버전 변화, 한 줄 설명, 다음 종까지 남은 시간, "나중에" · "업데이트")이 뜬다. 승인해야만 설치하고 다시 실행한다.
- [ ] 다음 종까지 2분이 안 남았거나 종이 울리는 중이면 "업데이트" 단추가 잠기고 "종이 울린 뒤에 할 수 있어요"가 보인다.
- [ ] 다시 실행되면 창을 열고 "<버전>으로 업데이트했어요" 알림을 보여 준다.
- [ ] 버전 줄의 세 모습, 주황 점, 모달, 잠금이 가짜 업데이트 상태를 넣은 테스트로 확인된다. `--data-dir`로 띄운 테스트 실행은 실제 릴리스를 확인하지 않는다.
- [ ] 실제 릴리스가 아직 없어 내려받기부터 재실행까지의 전체 흐름은 이 티켓에서 확인하지 못한다. 티켓에 그렇게 적는다.
- [ ] 타입 검사, 린트, 전체 자동 테스트가 통과한다.

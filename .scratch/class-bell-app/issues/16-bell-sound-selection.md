# 종소리 청취 시안과 음원 확정

Type: prototype
Status: resolved
Blocked by: 06, 15, 20

## Question

v1에 내장할 종소리는 무엇인가? 레퍼런스 조사에서 나온 후보 묶음을 단독 HTML 청취 시안(재생 버튼이 달린 페이지)으로 만들어 사용자가 직접 듣고 고른다.

- 시작종과 끝종 각각의 후보를 나란히 들을 수 있게 한다. 기본값이 될 내장 음원 짝 하나와, 음원 목록에 함께 넣을 나머지 내장 음원을 정한다([종소리 정책 결정](06-bell-policy.md)).
- 강아지 테마 소리는 채택 후보가 아니라 비교용으로만 한 번 넣는다.
- [한국 중 · 고등학교 수업 종 음원 조사](20-korean-school-bell-sounds.md)의 결과를 후보에 반영한다.
- 고른 음원의 출처, 라이선스, 필요한 출처 표기를 함께 확정한다.
- 길이나 음량 다듬기처럼 음원에 손볼 것이 있으면 목록으로 남긴다.

## Answer

사용자가 청취 시안(`assets/16-bell-sounds.html`)을 듣고 확정한 내용이다.

내장 음원:

- v1의 내장 음원은 여섯 짝, 열두 개다. 모두 직접 합성한 소리이고 음색은 "부드러운 차임" 하나다.
- 기본값 짝은 웨스트민스터 차임이다. 처음 설치했을 때 시작종은 앞 2소절, 끝종은 뒤 2소절이다.
- 시작종은 끝종의 멜로디를 포함하지 않는다(사용자 요청으로 4소절 전체에서 앞 2소절로 줄였다).

| 짝 | 시작종 | 끝종 | 길이 |
|---|---|---|---|
| 웨스트민스터 차임 (기본값) | 앞 2소절: 파 라 솔 도 / 파 솔 라 파 | 뒤 2소절: 라 파 솔 도 / 도 솔 라 파 | 각 8.6초 |
| 4음 딩동댕동 | 도 미 솔 도 (올라감) | 도 솔 미 도 (내려감) | 각 4.3초 |
| USB 꽂는 소리 / 빼는 소리 느낌 | 미 → 시 (짧게 올라가는 두 음) | 시 → 미 (내려가는 두 음) | 각 2.0초 |
| 5음 음계 차임 | 솔 라 도 레 미 | 미 레 도 라 솔 | 각 4.3초 |
| 빠른 아르페지오 | 도 미 솔 도 미 솔을 빠르게 훑어 올라감 | 같은 음을 훑어 내려감 | 각 2.7초 |
| 화음 차임 | 화음 세 번: 도미솔, 파라도, 솔시레 | 화음 세 번: 솔시레, 파라도, 도미솔도 | 각 5.0초 |

- 정확한 음높이, 음 길이, 빠르기, 음색의 배음 구성은 시안 파일의 `SCORES`와 `TIMBRES.chime`에 있다. 스펙은 이 값을 원본으로 삼는다. 길이는 마지막 음이 사라지는 여운 1.6초를 포함한 값이다.
- 음원 목록에서 열두 개가 각각 어떤 이름으로 보일지는 정하지 않았다. 스펙에서 정한다.

쓰지 않는 것:

- 파일 음원 후보(Freesound · 위키미디어 공용의 학교 차임, 안내방송 차임, 실로폰 · 오르골 징글, 핸드벨)는 모두 쓰지 않는다. 사용자가 듣고 쓸 수 없다고 판단했다.
- 3음 딩동댕, 소녀의 기도 / 엘리제를 위하여 합성판도 쓰지 않는다.
- 강아지 테마 소리는 비교용으로 들었고 [종소리 정책 결정](06-bell-policy.md)대로 내장하지 않는다.
- 합성 음색 "오르골"과 "멜로디 칩풍"은 쓰지 않는다.

출처와 라이선스:

- 내장 음원은 모두 이 프로젝트가 직접 합성한 것이라 외부 음원의 라이선스가 걸리지 않고 출처 표기도 필요 없다.
- 웨스트민스터 차임의 멜로디는 1793년 작곡으로 저작권이 없다([종소리 레퍼런스와 음원 출처 조사](15-bell-sound-references.md)).
- "USB 꽂는 소리 / 빼는 소리 느낌"은 Windows의 실제 효과음을 쓰지 않는다. 그 소리는 Microsoft 저작물이라 내장할 수 없다. 짧게 오르내리는 두 음으로 비슷한 느낌만 낸 것이고, 음은 에이전트가 정했다. 실제 효과음과 비교하지는 않았다.

구현 때 손볼 것:

- 짝마다 들리는 크기가 다를 수 있다. 시안에서는 맞추지 않았다. 내장 음원끼리 크기를 맞춘다.
- 화음 차임은 여러 음이 겹친다. 찌그러지지 않는지 확인한다.
- 내장 음원을 앱에 담는 방식(빌드 때 파일로 만들어 넣을지, 실행 중에 합성할지)은 정하지 않았다. 음원 목록이 내장 음원과 등록 음원을 같은 방식으로 다루려면 빌드 때 파일로 만드는 쪽이 단순하다(에이전트의 제안).

확인하지 못한 것:

- 에이전트는 소리를 귀로 듣지 못했다. 합성 음원이 신호를 내고 최대값이 1을 넘지 않는 것은 처음 여덟 곡에 대해서만 오프라인 렌더링으로 확인했다. 뒤에 더한 USB 느낌, 5음 음계, 빠른 아르페지오, 화음 차임은 스크립트 문법만 확인했고 소리는 사용자가 들은 것이 전부다.
- 실제 실습실의 PC 스피커에서 들리는지는 구현 뒤 수동 통합 테스트에서 확인한다.

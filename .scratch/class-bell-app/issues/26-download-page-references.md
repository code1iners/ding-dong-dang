# 내려받기 페이지 레퍼런스와 제공 경로 조사

Type: research
Status: resolved
Blocked by: 

## Question

학원 사이트(`https://pet-grooming-cdh.squadify.app/`, 소스는 `~/workspace/personal/pet-grooming-cdh`)의 어느 경로에서 앱을 내려받게 하는 것이 좋은가? [배포와 설치 방식 결정](11-distribution-decision.md)에서 사용자가 요청했다. 사용자는 그 경로에서 내려받기 버튼을 누르면 내려받는다.

- 기관 · 서비스 사이트가 자기 데스크톱 앱이나 내부용 도구를 내려받게 하는 방식의 레퍼런스(경로 이름, 메뉴에 드러내는지, OS 자동 감지, 버튼과 설치 안내 · 영상의 배치).
- 학원 사이트의 현재 구조(라우팅, 배포 방식)에서 새 경로를 더하는 방법과 제약.
- 경로 후보와 추천안. 공개 홈페이지의 방문자(수강 희망자)에게 노출되는 정도, 검색 엔진 노출 여부를 함께 본다.

## Answer

조사 문서: `research/download-page-references` 브랜치(커밋 `f7d5759`)의 `docs/research/download-page-references.md`.

확인 방식: 레퍼런스 15곳을 열어 정적 HTML을 읽었다(스크립트가 그리는 OS 자동 감지 화면은 미확인). 학원 사이트 폴더는 읽기만 했고 빌드 실험은 복제본에서 했다. 경로 응답은 로컬 `wrangler dev`로만 확인했다.

레퍼런스의 패턴:

- 경로 이름은 `/download`가 가장 많다(Obsidian, Ollama, Zotero, Zoom). 앱이 주목적이 아닌 사이트는 놓인 것의 이름을 쓴다(Notion `/desktop`).
- 앱이 곧 제품이 아닌 사이트는 메뉴 깊은 곳이나 푸터에 두거나 상단 메뉴에 두지 않는다.
- OS 처리는 접속 OS에 맞춘 큰 버튼 하나와 "다른 버전" 링크, 또는 모든 OS를 나란히 두는 두 갈래다. 버튼 글귀에 OS 이름이 들어간다.
- 서명 없는 앱의 경고 안내를 내려받기 링크 바로 위에 둔 사례가 있다(Pulsar). 내려받기 페이지 안에 설치 영상을 넣은 사례와, 학원 · 기관이 직원용 도구를 내려받게 하는 한국어 사례는 찾지 못했다.

경로 후보와 추천:

- 후보는 `/download/`, `/app/`, `/apps/ding-dong-dang/`, 하위 도메인이다. 추천은 `/app/`이다(가장 짧아 말로 전하기 쉽다). 수강 희망자와 검색 엔진에 드러나는 정도는 경로 이름이 아니라 메뉴에 링크를 넣는지와 `noindex`로 정해진다.
- 함께 권하는 구성: 페이지에 `noindex` 메타를 넣고 `sitemap.xml`에는 넣지 않으며(`robots.txt`로 막으면 `noindex`를 읽지 못한다), 첫 페이지에 링크를 두지 않고 직원에게 주소나 QR로 전한다.

GitHub Releases 버튼:

- 고정 주소 `https://github.com/<소유자>/<저장소>/releases/latest/download/<파일 이름>`은 302 두 번 뒤 첨부 파일 응답으로 끝난다. 파일 이름이 릴리스마다 같아야 하고 릴리스가 초안 · 사전 릴리스가 아니어야 한다.
- 다른 출처에서는 `download` 속성이 무시되므로 평범한 링크로 둔다. `public/_redirects`로 사이트의 같은 출처 주소가 GitHub로 넘기게 할 수도 있다.

학원 사이트에 더할 때의 제약:

- 별도 저장소(`code1iners/pet-grooming-cdh`)이고 `main`에 push하면 운영에 배포된다.
- Vite 다중 페이지 입력은 그대로는 빌드가 실패한다(`vite.config.ts`의 플러그인이 모든 HTML에 실행된다). 플러그인을 첫 페이지에만 적용하게 고치면 통과한다. `public/<경로>/index.html`에 완성 HTML을 두면 설정 변경이 없지만 사이트의 스타일을 공유하지 못한다.
- 첫 페이지에 상대 주소 링크를 넣거나 `sitemap.xml`에 새 페이지를 넣으면 기존 테스트가 실패한다. 새 페이지는 기존 검사 대상이 아니다.
- Workers 정적 자산은 파일 하나 25 MiB 한도가 있어 영상 크기에 걸릴 수 있다.

미확인: 운영 배포에서의 응답, 실제 브라우저에서 버튼을 눌렀을 때의 동작과 경고 문구, 영상 파일 크기와 둘 곳, 네이버 등의 `noindex` 처리.

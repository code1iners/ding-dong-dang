# 02: 먼저 할 정리: 문서 고치기와 e2e 준비 데이터 한 곳에 모으기

**What to build:** 바뀐 용어와 화면 계약이 문서에 먼저 적히고, e2e들이 시간표 준비 데이터를 도우미 하나로 만든다. 앱 동작은 바뀌지 않는다. 03에서 데이터 모양을 바꿀 때 e2e는 이 도우미만 고치면 된다. [스펙](../spec.md)의 Implementation Decisions "문서 변경"과 Further Notes "알려진 위험 · e2e 고칠 범위"를 따른다.

Blocked by: 01

Status: ready-for-agent

- [ ] `GLOSSARY.md`에서 "요일 배정"을 지우고 "시간대", "쓰는 시간표"를 더하며 "시간표"의 정의를 고친다(스펙 "용어"의 정의와 _Avoid_ 그대로).
- [ ] `docs/adr/0003-single-active-timetable.md`가 있다: 요일마다 배정하던 구조를 버리고, 시간표가 시간대를 가지며, 종은 쓰는 시간표 하나만 따른다. 이유는 "보통 시간표 하나만 쓰고, 여러 개는 예외 대비"다. 기존 ADR 형식을 따른다.
- [ ] `DESIGN.md`의 시간표 화면 설명이 목록 · 상세로 바뀌고, "시간표 선택 창은 다섯 줄 반"이 지워지고, 요일 동그라미의 마우스 이름 문장이 "카드 · 상세의 이름"으로 바뀌고, 지우기 규칙이 스펙 "지우기"대로 바뀌고, 현황에 쓰는 시간표 이름이 더해진다.
- [ ] v1 스펙(`.scratch/class-bell-app/spec.md`)의 "시간표와 요일 배정", "저장"의 `Data`, 강아지 그리는 횟수 문장에 "[시간표 다시 만들기 스펙]이 대신한다" 안내가 붙는다(본문은 남긴다).
- [ ] 시간표 데이터를 직접 만들어 넣는 e2e(`status`, `bell-playback`, `update`, `dog`, `roaming-dog`, `accessibility`, `app-shell`, `bell-screen`, `timetable`, `period-editing`)가 공용 도우미 하나로 준비 데이터를 만든다. 도우미의 입력은 "시간표 이름 · 요일 · 수업 시간"처럼 03 이후에도 뜻이 같은 모양으로 둔다.
- [ ] 도우미 밖에서 `weekdays`나 저장 파일의 시간표 모양을 직접 쓰는 e2e가 없다(`grep`으로 확인).
- [ ] `DESIGN.md`와 GLOSSARY의 바뀐 문장 사이에 서로 다른 말이 없다(용어 "시간대", "쓰는 시간표", "쓰는 중"으로 통일).
- [ ] 마지막 변경 뒤 `npm run check`가 통과한다(동작 변경 없음).

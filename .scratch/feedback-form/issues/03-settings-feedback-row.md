# 03: 설정 화면의 "의견 보내기"

**What to build:** 학원 강사가 설정 화면의 "의견 보내기" 줄에서 "보내기"를 누르면, 기본 브라우저에서 앱 버전과 OS가 채워진 딩동댕 제보 폼이 열린다. [스펙](../spec.md)의 Implementation Decisions "딩동댕 메인 프로세스" · "딩동댕 설정 화면" · "문서"와 Testing Decisions를 따른다. 화면은 `DESIGN.md`를 따르고, 다르면 멈추고 사용자에게 확인한다.

Blocked by: 02

Status: done

- [x] 메인 쪽 순수 함수가 앱 버전 · 플랫폼 · 시스템 버전으로 폼 주소를 만든다. 호스트는 01에서 정한 주소의 상수, 경로는 `/form/ding-dong-dang`, `os`는 `macOS <버전>` / `Windows <버전>`, 값은 URL 인코딩한다.
- [x] 렌더러 → 메인 명령 "의견 보내기 폼 열기"가 있고, 메인은 그 주소를 `shell.openExternal`로 연다. 서버 상태를 미리 확인하지 않고, 설정 화면을 열거나 앱을 띄울 때 n8n으로 요청하지 않는다.
- [x] 설정 화면에서 버전 줄 바로 아래, "모든 데이터" 바로 위에 "의견 보내기" 줄이 있다. 보조 글자 "버그나 불편한 점", 작은 옅은 단추 "보내기"와 바깥으로 나가는 화살표 SVG 아이콘, 화면 읽기 이름 "의견 보내기 폼 열기". 새 색 · 새 부품 없이 토큰만 쓴다.
- [x] `DESIGN.md` 설정 화면 항목 순서에 "의견 보내기"가 버전과 모든 데이터 사이에 있다.
- [x] README에 "의견 보내기" 절이 있다: 여는 곳, 보내는 것(쓴 내용, 선택한 이메일과 스크린숏, 앱 버전과 OS), 개발자만 본다는 것, 시간표 · 종소리 등 앱 데이터는 보내지 않는다는 것. "~해요"체.
- [x] 단위 테스트: 주소 함수의 macOS · Windows `os` 값, 인코딩, 호스트 · 경로.
- [x] 설정 화면 렌더 테스트: 줄 순서(버전 → 의견 보내기 → 모든 데이터)와 단추의 이름. 기존 "버전 줄이 '모든 데이터' 바로 위" 테스트를 새 순서에 맞게 고친다.
- [x] README 링크 테스트의 "요구된 절"에 "의견 보내기"가 있다.
- [x] e2e: `shell.openExternal`을 가로채, 마우스로 누를 때와 키보드로 초점을 옮겨 누를 때 모두 경로 `/form/ding-dong-dang`, `version` = 앱 버전, 비어 있지 않은 `os`의 주소가 열리는지 확인한다.
- [x] 개발 Mac에서 주소 함수가 만든 실제 주소에 `curl`로 GET하면 200이다(02의 폼이 열린다).
- [x] 마지막 변경 뒤 `npm run check`가 통과한다.
